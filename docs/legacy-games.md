# 기존 앱 분석 — 「Step Up 4 · Movie Quiz」

> 대상: 저장소 최상단 `index.html` (2,878줄, 약 456KB) + `Code (6).gs` (Apps Script, 112줄)
> 기획서가 말하는 "쿠키런형 · 인형뽑기 · 카트레이싱" 세 게임이 모두 이 한 파일 안에 들어 있다.
> 목적: 구조와 장단점을 정리하고, 새 게임으로 **무엇을 가져오고 무엇을 버릴지** 정한다.

---

## 1. 전체 구조

| 항목 | 내용 |
|---|---|
| 형태 | HTML 한 장 (CSS·JS·이미지 모두 인라인). 빌드 도구 없음, 순수 JavaScript |
| 이미지 | 로고·영화 포스터 base64 약 160KB. 캐릭터·소품은 전부 **코드로 그린 SVG** |
| 배포 | Apps Script `doGet`(HtmlService) 또는 GitHub Pages + `doPost` 두 방식 모두 지원 |
| 화면 | `start` → `quiz` → `result` → `final`(시상대) 4개 `section.screen`을 `show(id)`로 전환 |
| 소리 | Web Audio로 **직접 합성**: 16스텝 시퀀서 배경음 13곡(s1·s2·s3·disco·break·pop·crew·run·kart·pyramid·finale·ma·boo) + 효과음(`sfxOk/sfxNo/sfx`). 음원 파일 없음 → 저작권 안전 |
| 저장 | 진행 상황 저장 없음 (새로고침하면 처음부터) |

### 퀴즈 흐름
- 3단계 × 10문제: 1단계 단어(영영풀이·빈칸, 30초) / 2단계 문법 O·X + 고쳐 쓰기(40초) / 3단계 단어 배열 영작(60초, **함정 단어 1개** 섞음)
- 정답이면 자동으로 다음 문제, 오답이면 정답·해설 카드 → [다음 ▶] 버튼
- **누적 정답 수 이벤트** `CORRECT_MILESTONES`: 5 디스코 / 10 인형뽑기 / 13 브레이킹 / 15 쿠키런 / 18 카트 / 20 인형뽑기 재도전 / 23 쿠키런 재도전 / 25 팝핀 / 27 토끼춤. 오답 5개마다 "정신 차리라, 마!" 연출
- 초코파이 찬스: 최고 난도 1문제, 맞히면 상품
- 최종 화면: 시상대 + 순위 + 보너스 게임(상품 없음)

### 구글 시트 연동 (`Code (6).gs`)
- `doPost`가 `{fn, args}` 를 받아 `saveResult / savePrize / saveFinal / getRanking` 실행
- 브라우저는 `fetch(..., {headers: 'text/plain'})` 로 보냄 → **CORS 사전 요청을 피하는 검증된 방식**, 학생 구글 로그인 불필요
- `google.script.run` 을 흉내 내는 Proxy로 Apps Script 안팎 어디서나 같은 코드가 돈다
- `LockService` 로 동시 저장 충돌 방지, 시트가 없으면 헤더째 자동 생성, 상품 탭에 **지급 완료 체크박스**
- 순위: 이름별 최고 점수, 동점이면 짧은 시간 우선

## 3. 장점 — 그대로 가져올 것

1. **Web Audio 합성 음악·효과음 엔진** — 저작권 문제 없음. 시상식 팡파르(`finale`)도 이미 있음. 그대로 모듈로 분리해 재사용
2. **Apps Script 연동 방식** (`doPost` + `text/plain` fetch + LockService + 시트 자동 생성 + 체크박스) — 기획서 8번 시트 구조(`기록/오답/상품`)로 탭 이름만 바꿔 확장
3. **게임 감각 튜닝 값** — 점프 중력·초속, 무적 시간, 집게 판정 범위, 카트 가속 단계 등은 이미 학생들이 해 본 수치. 새 엔진(Phaser)에서도 출발값으로 사용
4. **연출 문법** — 3·2·1·GO 카운트다운, POWER UP 변신, 승리 시 캐릭터 춤, 펑! 파티클, 화면 하단 안내 메시지 한 줄
5. **모바일 조작 UI** — 엄지로 누르는 큰 버튼, 핸들/페달 분리, `pointerdown` 기반 (iOS 사파리에서 검증됨)
6. **테스트용 훅** (`window.__RG`, `window.__KG`) — 자동 테스트·스크린샷 점검에 유용, 새 게임에도 유지
7. **오답 해설 카드 + 함정 단어 영작** — 유형 12 "단어 타일 대체 방식"에 3단계 배열 UI를 그대로 활용 가능

## 4. 단점 — 고칠 것

| # | 문제 | 새 게임에서 |
|---|---|---|
| 1 | **미니게임이 학습과 무관** (보상용 순수 액션) | 기획서 4번대로 아이템·적·레인에 단어/청크를 붙여 학습과 직결 |
| 2 | 파일 하나 2,878줄, 문제가 코드 안에 하드코딩 | Vite 모듈 구조, 문제는 `data/questions/*.json` |
| 3 | **실존 학생 이름이 캐릭터에 들어 있음** (장애물 아이 SVG의 명찰) | 개인정보 → 새 게임에서는 전부 가상 캐릭터 |
| 4 | "COOKIE RUN" 이름, 영화 「Step Up」 포스터 이미지(base64) | 저작권 → 이름·그래픽 모두 독창적으로 (기획서 4번) |
| 5 | 쿠키런 약 28초, 점프만 있음, 맵 1개 고정 | 2배 길이(약 60초), 슬라이드 추가, 구간별 미션, 보스 구간 |
| 6 | 인형뽑기에 단계·난이도 없음 | 품사 모드 → 순서대로 뽑아 문장 완성 모드, 연속 정답 = 집게 힘 |
| 7 | 카트 AI 4대 | 기획서대로 라이벌 2대로 줄이고 품사 게이트·아이템 박스 퀴즈 추가 |
| 8 | 2D 평면 그래픽, 화면 크기 고정값(H=300 등) | 3D 보드(Three.js) + Phaser 반응형 스케일 |
| 9 | 진행 상황 저장 없음 | localStorage 자동 저장 + 이어하기 (PWA) |
| 10 | 시트 연결 실패 시 **가짜 순위**(`fakeRanking`: 민준·서연…)를 보여 줌 | 오프라인이면 "기록 전송 대기 중"으로 솔직하게 표시하고 나중에 재전송 |
| 11 | 웹앱 URL이 HTML에 하드코딩 | `config.json` 으로 분리 |
| 12 | 상품 판정이 전부 브라우저 | 기획서대로 쿠폰 코드 + 선생님 PIN 으로 사용 처리 |
